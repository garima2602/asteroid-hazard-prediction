# Asteroid Hazard Prediction

An end-to-end machine learning project predicting whether a Near-Earth Object
(asteroid) is potentially hazardous, based on NASA orbital and physical data —
now extended from the original notebooks into a full-stack web app: a live
hazard predictor, an EDA dashboard, model explainability views, and a
conceptual 3D close-approach viewer.

## App Architecture

```
asteroid/
├── asteroidhazard.ipynb          # original EDA + from-scratch logistic regression notebook
├── asteroidhazardmodels.ipynb    # original multi-model (RF/LightGBM/SMOTE) notebook

├── backend/

│   ├── train.py                  # trains the model, writes every artifact below
│   ├── main.py                   # FastAPI app serving predictions + precomputed stats
│   ├── schemas.py                # pydantic request/response models
│   ├── requirements.txt          # deps for running the API
│   └── artifacts/                # generated by train.py (model.pkl, metrics.json, ...)

    ├── src/
    │   ├── pages/                 # Predictor, Dashboard, Insights, OrbitPage
    │   ├── components/
```

### Why the app uses a different feature set than the notebooks

`asteroidhazard.ipynb` drops diameter/velocity/miss-distance columns before
training; `asteroidhazardmodels.ipynb` trains on the full JPL Small-Body
Database (thousands of one-hot orbit/class columns, 456 MB) which isn't
practical to expose as a web form. `backend/train.py` instead trains a fresh
`RandomForestClassifier` directly on the original NASA NEO dataset using the
10 physically meaningful fields a form needs (diameter, velocity, miss
distance, magnitude, orbital period, semi-major axis, eccentricity,
inclination, MOID) — same dataset, a form-friendly feature set.

Note: this model reaches ~99.7% accuracy / ROC-AUC ≈ 1.0. That isn't
overfitting — NASA's own Potentially Hazardous Asteroid definition is a
deterministic rule on two of these inputs (MOID ≤ 0.05 AU and H ≤ 22), so a
model given those inputs recovers that rule almost exactly. This is called
out directly on the Model Insights page rather than hidden.

## API Specification (`backend/main.py`)

| Method | Path                    | Description                                              |
|--------|-------------------------|------------------------------------------------------------|
| GET    | `/api/health`           | Liveness + whether the model is loaded                    |
| GET    | `/api/feature-ranges`   | Min/max/mean/median/std per feature (drives slider bounds) |
| GET    | `/api/metrics`          | Accuracy, precision, recall, F1, ROC-AUC, confusion matrix, ROC curve points |
| GET    | `/api/feature-importance` | Random forest feature importances, sorted desc           |
| GET    | `/api/eda`               | Row/class counts, per-feature histograms (hazardous vs. not), correlation matrix |
| POST   | `/api/predict`           | Body: the 10 features below → hazard probability, risk level, top contributors |

`POST /api/predict` request body:

```json
{
  "absolute_magnitude": 18.5,
  "est_diameter_min_km": 1.2,
  "est_diameter_max_km": 2.6,
  "relative_velocity_kph": 60000,
  "miss_distance_km": 500000,
  "orbital_period_days": 700,
  "semi_major_axis_au": 1.6,
  "eccentricity": 0.5,
  "inclination_deg": 15,
  "min_orbit_intersection_au": 0.02
}
```

Response:

```json
{
  "hazardous": true,
  "probability": 0.9627,
  "riskLevel": "Critical",
  "riskColor": "#ef4444",
  "topContributors": [
    { "feature": "est_diameter_max_km", "label": "Est. Diameter Max (km)", "value": 2.6, "importance": 0.4415 }
  ]
}
```

Risk bands: `< 25%` Low · `25–50%` Moderate · `50–75%` High · `≥ 75%` Critical.

## Quickstart

### 1. Backend (FastAPI)

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Train the model + generate all artifacts (only needed once, or after changing data/nasa.csv)
python train.py

# Start the API
uvicorn main:app --reload --port 8000
```

Verify it's up: `curl http://localhost:8000/api/health`

### 2. Frontend (Vite + React + Tailwind)

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the printed URL (default `http://localhost:5173`). The dev server proxies
`/api/*` to `http://localhost:8000`, so both must be running.

### 3. Production build

```bash
cd frontend
npm run build      # outputs to frontend/dist
npm run preview    # serve the production build locally
```

Serve `frontend/dist` behind any static host, and point `vite.config.js`'s
proxy (or a reverse proxy in front of the API) at wherever `uvicorn` runs in
production.

## App Tech Stack

- **Frontend:** React 19 + Vite, Tailwind CSS v4, Recharts, React Three Fiber
  + drei (3D), react-router-dom, lucide-react, axios
- **Backend:** FastAPI, scikit-learn (RandomForestClassifier), pandas, joblib
- **Data:** NASA Near-Earth Object dataset, 4,687 objects, 755 hazardous (16.1%)

## Original Notebook Project

The sections below document the original notebook work (`asteroidhazard.ipynb`,
`asteroidhazardmodels.ipynb`) that the app above is built on top of.

### Key Learnings
- Handling imbalanced datasets using SMOTE
- Comparing multiple ML models
- Feature importance analysis
- Building an end-to-end ML pipeline

### Dataset
- Source: NASA Near-Earth Object (NEO) dataset
- Total Records: ~4,687
- Total Features: 40

**Key Features:** Absolute Magnitude (brightness), Estimated Diameter, Relative
Velocity, Orbital Period, Perihelion Distance, Mean Motion

**Target Variable:** `pha` → Potentially Hazardous Asteroid (Y/N)

### Project Pipeline

Data → Cleaning → Feature Engineering → Encoding → Scaling → SMOTE → Model Training → Evaluation

### Handling Imbalanced Data

The dataset was highly imbalanced (very few hazardous asteroids). Addressed by
applying **SMOTE (Synthetic Minority Oversampling Technique)** to balance
classes before training.

### Models Used
- Logistic Regression
- Random Forest
- LightGBM

### Results

**Logistic Regression**
- Accuracy: 99.25% · Precision: 0.70 · Recall: 0.95 · F1: 0.78

**Random Forest (best notebook model)**
- Accuracy: 99.89% · Precision: 0.95 · Recall: 0.95 · F1: 0.95

**LightGBM**
- High performance with tuned parameters

### Feature Importance (Random Forest)

Top features influencing predictions: MOID (Minimum Orbit Intersection
Distance), Orbital Eccentricity, Semi-major Axis, Absolute Magnitude

### Notebook Tech Stack

Python, Pandas, NumPy, Scikit-learn, LightGBM, Imbalanced-learn (SMOTE),
Matplotlib, Seaborn
